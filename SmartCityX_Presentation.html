MODULE 1 — CO1

String Algorithms

Pattern matching algorithms that power the city's search and alert detection systems.

🔍 KMP — Knuth-Morris-Pratt
City Use: Smart Search — searches citizen reports and documents

Builds a failure function to avoid re-checking characters.
Never backtracks more than N steps.

Time: O(N+M)Space: O(M)
🎯 Rabin-Karp
City Use: Infrastructure code search — finds IDs like INF-2024-WATER

Uses rolling hash — updates hash in O(1) per step.
Average case same as KMP but handles multiple patterns.

Time: O(N+M) avgSpace: O(1)
🚨 Aho-Corasick
City Use: Emergency detection — scans text for fire, flood, gas leak, accident simultaneously

Builds a trie + BFS failure links. Scans text once detecting all keywords.

Time: O(N+M+Z)Space: O(M×Σ)
🔁 Z-Function
City Use: Detect repeated phrases in city reports (e.g., "pipe burst" repeated 3 times)

Computes Z-array where Z[i] = length of longest prefix starting at i.

Time: O(N+M)Space: O(N+M)

KMP — DEEP DIVE

KMP in SmartCityX

How it Works

  • Step 1: Build failure function from pattern in O(M)
  • Step 2: Scan text left to right — never move text pointer back
  • Step 3: On mismatch, use failure table to skip ahead
  • Step 4: Report all match positions
// Pattern: "water" in citizen report
Text: "emergency water leak zone-A"
Fail[]: [0, 0, 0, 0, 0]
Match at position: 10
Comparisons: 31 (vs 150 for naive)

City Application

Smart Search Page
User types "water leakage" → Java KMP searches all 30 reports + 15 documents → returns match positions + failure table
Why KMP over Naive?
Naive: O(N×M) — rescans characters
KMP: O(N+M) — failure function prevents backtracking

For 30 reports × avg 200 chars: KMP saves ~80% comparisons

AHO-CORASICK — DEEP DIVE

Aho-Corasick in SmartCityX

Construction

  • Step 1: Insert all emergency keywords into a Trie
  • Step 2: Build failure links using BFS (like KMP but for trie)
  • Step 3: Build output links — propagate matches
  • Step 4: Scan city text once — detect all keywords simultaneously
Emergency Keywords (16 patterns)
fire · flood · accident · gas leak · explosion · injured · ambulance · emergency · danger · critical · blackout · collapse · leak · smoke · trapped · casualties

City Application — Two Places

1. Emergency Scanner
User pastes any text → Java scans once → all matching keywords highlighted with position → Emergency Level: CRITICAL / HIGH / MEDIUM
2. Report Category Detection
Citizen submits report → Java Aho-Corasick scans description → auto-assigns category (Water / Traffic / Emergency / Infrastructure)
Time: O(N + M + Z) Z = number of matches Single scan for all patterns

MODULE 2 — CO2

Suffix Structures

Document indexing and similarity algorithms for city infrastructure documents.

📑 Suffix Array (O(N log N))
City Use: Index city documents for fast substring search

Sorts all suffixes of a document lexicographically. Binary search finds any pattern in O(M log N).

Build: O(N log N)Search: O(M log N)
⚡ SA-IS (O(N))
City Use: Large-scale document indexing where O(N log N) is too slow

Linear time suffix array using Induced Sorting. Classifies suffixes as S-type or L-type.

Build: O(N)Space: O(N)
📊 LCP / Kasai Algorithm
City Use: Document similarity — finds Longest Common Substring between two city documents

Kasai builds LCP array in O(N) after suffix array. LCP[i] = common prefix length between adjacent suffixes.

Build: O(N)Space: O(N)
🤖 Suffix Automaton
City Use: Fast substring existence queries — "does this pattern appear in this document?"

Builds a DAG of all substrings in O(N). Query any substring in O(M).

Build: O(N)Query: O(M)
7 / 15
SUFFIX ARRAY + LCP — DEEP DIVE

Document Similarity in SmartCityX

Algorithm Steps (Java)

  • Step 1: Concatenate docA + separator + docB
  • Step 2: Build Suffix Array on combined string in O(N log N)
  • Step 3: Run Kasai's algorithm → LCP array in O(N)
  • Step 4: Scan adjacent suffix pairs where one is from docA, other from docB
  • Step 5: Maximum such LCP = Longest Common Substring
  • Step 6: Similarity score = (2 × LCS length) / (len_A + len_B) × 100%

City Application

Documents Page — Live Demo
Doc A: "road maintenance sector 12 water pipeline"
Doc B: "road maintenance water supply repair"

→ LCS: "road maintenance " (17 chars)
→ Similarity: 31%
→ Java execution: 1.02 ms
Why useful for a city?
Detects duplicate reports, finds related infrastructure documents, identifies common service descriptions across departments

MODULE 3 — CO3

Advanced Dynamic Programming

Optimization algorithms for city resource management, query correction, and analytics.

✏️ Levenshtein Distance
City Use: Autocorrect citizen search queries

Minimum edits (insert/delete/replace) to transform one string to another. Wagner-Fischer DP table.

O(N×M) timeO(N×M) space
🔀 Damerau-Levenshtein
City Use: Better autocorrect — also handles transpositions (e.g. "serivce" → "service")

Adds transposition operation to Levenshtein. Catches adjacent character swaps.

O(N×M) timeO(N×M) space
⚡ Bitmask DP
City Use: Optimal city resource allocation within a budget

Evaluates all 2^N subsets of resources. Each bit = one resource included/excluded.

O(2^N × N) timeO(2^N) space
🔗 Matrix-Chain DP
City Use: Optimize city analytics pipeline operation order

Finds optimal parenthesization to minimize total multiplications. O(N³) DP.

O(N³) timeO(N²) space

BITMASK DP — DEEP DIVE

Resource Optimization in SmartCityX

How it Works

  • N resources → 2^N possible subsets (combinations)
  • Each subset represented as a binary bitmask (0/1 per resource)
  • Iterate all 2^N masks — compute total cost and value
  • Track mask with max value where cost ≤ budget
// N=8 resources → 256 combinations
mask = 00000101 → Fire Truck + Ambulance
cost = 25000+20000 = 45000 ≤ budget ✓
value = 90+95 = 185 pts → best so far

City Application

Resource Allocation Page
8 city resources: Fire Truck, Ambulance, Police, Rescue Team, Water Tanker, Repair Crew, HazMat, Electric Unit

User sets budget (e.g. ₹80,000) → Java evaluates 256 combinations → returns optimal set with coverage score
Why Bitmask DP?
Greedy fails — highest value resource might exceed budget. DP guarantees the global optimum by checking all 2^N subsets systematically.

Damerau-Levenshtein: "serivce" → distance = 1

USER ROLE

What the User Does

🔍 Smart Search Page
1. User types a keyword (e.g. "water leakage")
2. Selects algorithm: KMP / Rabin-Karp / Aho-Corasick
3. Java runs selected algorithm
4. Returns: match positions, failure table, comparisons, exec time
5. Misspelled? Java auto-corrects with Damerau-Levenshtein
🚨 Emergency Scanner
1. User opens Emergency page
2. Clicks "Open Scanner"
3. Pastes any text (news, alert message)
4. Java Aho-Corasick scans for 16 emergency keywords
5. Returns detected keywords + positions + emergency level
📋 Submit Citizen Report
1. User fills name, location, issue, description
2. Clicks "Submit & Auto-Detect Category"
3. Java Aho-Corasick scans description
4. Auto-assigns: Water / Traffic / Emergency / Infrastructure
5. Report appears at top of the list instantly

1. User selects Document A and Document B
2. Clicks "Run Similarity Analysis"
3. Java builds Suffix Array + LCP
4. Returns similarity %, LCS string, execution time
5. Useful for detecting duplicate or related documents
